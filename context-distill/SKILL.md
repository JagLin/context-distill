# context-distill

管一條鏈：**session → TRACKING.md（工作狀態）→ 給另一種讀者的文件**。三個模式：

| | capture | distill | compact |
|---|---|---|---|
| 觸發 | 手動：session 收尾時，或 context 用量高、要壓縮之前 | 手動 | 手動 |
| 輸入 | 還在 context 裡的 session | TRACKING 現況 | TRACKING 裡的 `superseded`／`closed`／`promoted` 標記 |
| 做什麼 | 新增記錄 | 換讀者 | 搬家 |
| 不變式 | session 裡說過的不丟；既有記錄只 supersede 不刪 | §1／§2／§4／檔頭不變；只寫 §6 與指標行 | 知識總量不變，只換位置 |

三者不合併：distill 承諾不動 §1／§2／§4／檔頭，compact 的工作就是動它們；capture 承諾既有記錄只 supersede、留在原位，compact 的工作就是搬走它們。合併任兩個就得放棄其中一個承諾。

每個區段恰好一個寫入者。例外只有指標行與 tombstone 兩種標記：它們是模式之間唯一的溝通管道，沒有它們三個模式接不起來。轉址更新不算例外——tombstone 是留在原位址的轉址，指向它的索引、交接段、跨檔引用不改也解析得到，只是多一跳；資訊已經在 tombstone 裡，再去更新指標是冗餘不是溝通。一旦「方便的寫入」也能成為例外，下一個就會跟進，一個寫入者的規則就只剩名字。

順序上 distill 在前 compact 在後（distill 產生 `promoted` 標記，compact 消耗它），但 compact 只看標記不做判斷，任何時候跑都安全。檔案大到 distill 讀不動時，先 compact 掉早已作廢的段落再 distill。

**不問。** 先假設再行動，把假設寫進輸出裡標明；這與專案 CLAUDE.md 的工作方式一致。

## 記錄類型與範圍

**範圍：一個 feature 資料夾一份 TRACKING.md。** 跨 feature 引用寫相對路徑加 § 號（`../nhi-upload/TRACKING.md §1.3`）。只有 distill 的 recurrence 偵測跨資料夾掃。

TRACKING.md 用固定骨架。**節號是位址，不是閱讀順序**：§1.n、ADR-n、OQ-n 與跨 feature 的 § 引用都掛在節號上，節號永遠不動；閱讀順序另外定義（見下方載入順序）。

| 節 | 內容 | 固定否 |
|---|---|---|
| 檔頭（不編號） | 交接段 | 固定，每份都有 |
| §0 | 這個 feature 是什麼 | 固定 |
| §1 | 已知事實；頂端一張主題索引 | 固定 |
| §2 | ADR | 固定 |
| §3、§5、§7 | feature 自用：欄位盤點、實作清單、工作分解、backlog、附錄等，內容不限 | 不固定，可空著 |
| §4 | Open Questions | 固定 |
| §6 | 方法論：該 feature 內長期有效的通則。只由 distill 寫入，capture 不碰 | 固定 |

比 §1 更優先的東西**不插 §0、不加子編號**，它屬於檔頭交接段。既有文件缺哪一節就在標準位置建，不回溯重排；charge 的檔頭「狀態」與 §6.1「給下一個 session 的話」兩處重寫制，標準裡合併為檔頭一處。證據等級、狀態符號這類小慣例以檔案裡已有的為準。

四種記錄類型：

| 類型 | 位置 | 寫入政策 | 裝什麼 |
|---|---|---|---|
| 交接段 | 檔頭，不編號 | **重寫**，只寫現在 | 現況到哪、先讀哪幾條 §、別再撿哪幾條——**只放指標，不放內容** |
| truth | §1 已知事實 | 追加＋supersede | 目前相信為真的事實，含**負向事實**（已否決的假設） |
| ADR | §2 | 追加＋supersede | 決定、放棄的選項、理由 |
| open questions | §4 | 狀態機：開 → 結案 → 索引一行 | 未解、未決、承諾 |

交接段是唯一重寫制的地方，也是唯一會摘要再摘要的地方，原話漂得最快。所以規則是它不承載任何事實：事實住在追加制的記錄裡，交接段是索引。每次重寫丟掉的只是舊索引。

§1 的定位是**暫存區**：還沒穩定的事實才留在這裡。穩定了就由 distill 升格、compact 搬走。§1 不是知識的最終住所。

### 標記

模式之間只靠三種標記溝通，拼法固定，各佔一行，放在該記錄標題的下一行（OQ 表格列則放在該列的問題欄開頭）：

```
superseded → §1.14 ｜ 2026-09-10
closed → §1.74 ｜ 2026-08-23
promoted → docs/charge/pricing-reference.md ｜ 2026-09-06
```

`superseded` 由 capture 寫在被推翻的 §1／ADR 上；`closed` 由 capture 寫在結案的 OQ 上；`promoted` 由 distill 寫在升格的 §1／ADR 上。指向欄一律是可解析的位址：§ 號、ADR-n、OQ-n、或檔案路徑。記錄本體不動，標記只是加一行。

拼法固定是為了 compact 能不讀整份檔案就找到候選：`grep -nE '(superseded|closed|promoted) → '` 列出的每一行就是一個候選單位。人寫的「已由 X 取代」「✅ 結案」之類仍可以留在標題裡給人看，但不算標記；沒有這三行的記錄對 compact 就是活的。

**session 的單位用日期近似**：不同日期視為不同 session。候選訊號裡的「N 個 session」一律換算成「N 個不同日期」。

**session 開頭載入順序**：交接段 → §4 → §1 只在動到該主題時讀對應小節 → 已升格的 reference 需要查找時才開。不要整份載入。

## capture

輸入：一段剛結束或即將被壓縮的 session。輸出：對 TRACKING 的追加、交接段的重寫、一段回覆摘要。

capture 要在壓縮**之前**跑：壓縮摘要會把使用者原話改寫成模型措辭，正是這個 skill 要防的漂移。這靠使用者自己注意 context 用量，不靠 hook。

### 抽取

按六項掃整個 session，寧可多撈：

1. 遇到的困難與怎麼處理的
2. 提出、試過、放棄的做法，以及為什麼
3. 被要求、決定、同意、排除、確立為偏好／限制／邊界的事——**照原話**
4. 現在做到哪：什麼已完成、已確定
5. 還沒解決、還欠著、預期接下來要發生的事
6. 難以重建的細節：名稱、數字、日期、確切措辭、路徑、§ 引用——**照原樣**

兩種聲音權重不同：使用者說的、要的、確立的，貼近原話保留，用引號標記；模型自己的解釋和推理壓到只剩結論。使用者的約束一旦被改寫成模型措辭，會漂成「模型以為使用者的意思」，之後沒有 diff 能看出來。

### 分派

| 抽取項 | 去向 |
|---|---|
| (1) 困難 | **拆開**：學到的事實（含「假設 X 不成立」）→ §1，帶發現脈絡；處理過程 → 丟 |
| (2) 選項與取捨 | §2，與對應決定同一條 |
| (3) 決定／約束／偏好 | 決定 → §2；約束、偏好 → §1。使用者逐條拍板的標為決定，由決定推出但使用者未逐字拍板的**標為假設** |
| (4) 現況 | 交接段（重寫）；已完成的事只用來結案 §4，不另開記錄 |
| (5) 未解、承諾 | §4，新編號，帶日期；編號永不重用 |
| (6) 難重建細節 | §1，帶來源 |

**負向事實**：被推翻的假設是知識（「X 不成立」），不是事件，跟正向事實同區，發現脈絡欄寫否決依據和日期。保留判準：**模型有可能再自己推出來的假設才留**，純操作失誤不留。理由：正向推理下個 session 重推一次就有，但假設也會被重新生出來然後重試，負向結果是撞了牆才有的，無法便宜重推。

不為困難本身開區段。那會長成 issue tracker，單位是事件不是知識。

**發現脈絡**是 recurrence 偵測的原料：同一子系統下累積多條「在 X 壞掉時發現」，就是 dependency graph 缺一條邊的訊號。每條 §1 都要有。

### 寫入

- §1／§2／§4 只追加。同一件事已有記錄：更新該條並保留舊值（「原本 A，現在 B，因為…」）。判斷「已有記錄」不整份讀：先看 §1 主題索引，再 grep 關鍵字定位小節，只讀那一節。被推翻的整條加一行 `superseded → <新條>`，不刪、不搬（搬是 compact 的事）。
- §4 結案：加 `closed → <落地的 § 號>`，全文留在原位，等 compact。
- 交接段：整段重寫。內容限三類指標：現況到哪（一兩句）、先讀哪幾條 §、別再撿哪幾條 §1 負向事實。
- §1 頂端的主題索引：新增的 §1 條目順手掛進去；遇到指向 tombstone 的索引行，順手改指其去處。不改也只是多一跳，不是錯。

回覆摘要：追加了幾條、結案幾條、標為假設的有哪些、你自己拿不準去向的列出來。最後一行報數：「目前有 N 條 §1、M 條 ADR 符合升格條件」（條件見 distill）。只報數不動手。

## distill

輸入：TRACKING 現況（必要時含 archive）。輸出：升格草稿寫到目的地、一段聚合報告。**不動 §1／§2／§4／檔頭**；§6 是它的輸出區，promote 時在原記錄加一行指標。

蒸餾混了兩種工作：偵測候選、重排、換讀者是機械的，你做；真的穩了嗎、理由對嗎、讀者缺什麼前提是判斷，使用者看 diff 做。所以輸出直接是草稿，不包裝成審閱格式。

### 候選偵測

只用能從記錄讀出的訊號：

- **§1 → reference**：三個以上不同日期未被推翻、未被修改；被兩個以上不同日期的記錄或 § 引用過；沒有 §4 指著它。
- **ADR → explanation**：狀態 accepted，未被 supersede；沒有 §4 引用它；決定已落地（§1 有對應事實，或有實作證據）。
- **§4：永不升格。** 停滯的（三個以上日期沒動靜）列出來讓使用者決定結案或放棄。
- **recurrence**：跨所有 feature 資料夾，含 archive 和 tombstone 行，掃 §1 的發現脈絡。同一子系統或模組下兩條以上「在 X 壞掉時發現」的列成一組。這是唯一能碰到「沒被講出口的依賴」的訊號，放報告第一節。

### 目的地（按讀者定）

| 內容 | 去哪 | 讀者 |
|---|---|---|
| 穩定的 §1 事實 | 該 feature 的 reference（`docs/<feature>/` 正式文件，或 §1 主題索引指向的獨立檔） | 查找的人或 agent |
| 已落地的 ADR 的脈絡與取捨 | §6 方法論（該 feature 內長期有效的通則），或 `docs/<feature>/` | 之後動這個 feature、看不見岔路的人 |
| 跨 feature 的偏好與事實 | memory，且只放指標指回 TRACKING | 跨 session 的 agent |

不另設 `_promotion/` 之類的中間資料夾。目的地在檔案裡已經存在。

### 起草

**§1 → reference**：按元件／API／行為重排，發現順序丟掉，來源留腳註。措辭可整理，數字、名稱、確切行為不改。

**ADR → explanation**：讀者看不見岔路存在。草稿要回答：岔路是什麼、選了哪邊放棄哪邊、代價是什麼、什麼情況該重新考慮。使用者原話保留引號。最後一段固定寫**建議擺放位置**——哪個 code path 旁、哪份 checklist、哪個 README 段——explanation 只進文件庫的話，看不見岔路的人不會去讀。

**不補理由。** ADR 沒理由或只有半句，就在那一行寫 `[理由未在紀錄中出現]`。看 diff 的人速度快，最容易對看起來完整的段落放行，而編出來的理由在 diff 裡跟真的一模一樣。

### 報告與 promote

回覆裡附聚合報告，只放單一 session 的 diff 看不出來的：recurrence 組（第一節）、這次升格了哪幾條、停滯的 §4。三行寫得完就三行。

使用者看過 diff 沒問題後：對應記錄加一行 `promoted → <路徑> ｜ <日期>`，本體留著等 compact。使用者改了草稿裡的理由，把那句回填進原始 ADR。使用者不要某個候選，記 `promotion: rejected <日期>`，之後跳過直到該記錄有變化。

## compact

輸入：TRACKING 裡的三種標記（見「標記」）。先 `grep -nE '(superseded|closed|promoted) → '` 列出候選單位，只讀那些單位，不整份載入。輸出：archive 檔更新、原位 tombstone、一段報告。**不做判斷，不新增知識。**

這是 archive 第一次被正式定義；舊的 archive 檔是語意化之前的東西，**不回溯改寫**，recurrence 對它們只做 best-effort。

### 語意

- archive 是 write-only：沒有人讀它，唯一的讀取路徑是 recurrence 掃 tombstone。所以 archive 本體格式不重要，可掃描的表面全在 tombstone 上。
- **搬家的單位是可被引用的最小編號單位**：§1 的一個小節、一條 ADR、一個 OQ。跨檔引用指的是編號，編號的位址必須永遠解析得到，tombstone 就是留在該位址的轉址。比編號更小的東西沒有位址，不單獨搬。
- 硬條件：該單位裡的記錄**全部**帶 `superseded`、`closed` 或 `promoted` 標記。混著活記錄的單位不搬；裡面死掉的條目留原位帶標記。行數不是搬家依據。
- 升格的記錄也搬：reference 重排過措辭，archive 留原話與發現脈絡，兩者不重複。
- archive 檔一個 feature 資料夾一組，按月切（`archive-<年月>.md`），只為了單檔別太大。
- § 編號、ADR 編號、OQ 編號永不重用。

### tombstone

留在原位址，五個欄位缺一不可：編號、原因（作廢／結案／升格）、指向（新條目、落地 §、reference 路徑、或 archive 位置）、脈絡、日期。脈絡欄依類型：§1 填**發現脈絡**；ADR 填**被哪條取代與推翻原因一句**；OQ 填**落地成什麼**。

```
§1.9 ⚪ 已作廢 → ADR-006 ｜ 2026-08-20 ｜ 發現脈絡：對照 gen1 DBF 實測 DIAG_NO/PHYS_NO 欄型時發現
ADR-3 ⚪ 已被 ADR-9 取代 ｜ 2026-09-05 ｜ 推翻原因：「批價在櫃台就收斂」在案場不成立（編號示意）
OQ-40 ⚪ 已結案 → §1.74 ｜ 2026-08-23 ｜ 落地：那批「自費走定額」是事後改成自費的健保就醫
```

負向事實（已否決的假設）是活記錄，不因「假設被推翻」而算作廢；只有它本身帶 `superseded` 或 `promoted` 標記才搬。

小節內多條記錄若共用發現脈絡，一行寫完；不共用則一條一行。tombstone 可以多於一行，仍遠小於原文。

### 報告

列出這次搬了哪些單位，加上**不能搬但值得處理的**：某單位大部分已死、少數活著（例如 28/30），報「活的 N 條可考慮移到新編號」。使用者搬了之後舊單位全死，下次 compact 自然處理。compact 不替使用者搬活記錄。

瘦身有兩個受眾，判準不同：session 載入成本靠 compact；人讀不讀靠主題索引和 distill。一條事實可以對 session 已無用但對人仍值得看，反之亦然——compact 只處理前者。

## 不要做的事

- 不問使用者；假設並標明。
- 不把模型自己的推理寫成使用者的決定；未逐字拍板的標假設。
- 不為困難開區段；負向事實進 §1。
- 不讓任何事實只住在交接段。
- distill 只寫 §6 與指標行；compact 不做判斷、不搬混合單位、不回溯舊 archive；capture 不搬東西。
- 不替使用者補理由。
- 不升格 §4。
- 不跳過 explanation 的擺放位置。
- 不另設中間資料夾。
- 不整份載入 TRACKING。
- 不重排節號、不插節、不為優先事項加子編號；比 §1 更優先的東西進檔頭交接段。
